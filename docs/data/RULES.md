# 데이터 규칙 — 월 결산 현황판 (Sprint 2)

규칙 결정: 저장소 주인 (AI가 낸 초안 가운데 첫 번째 안을 그대로 채택, 2026-11-16) · 데이터: 전부 합성(가상 회사)

## 1. 칸
| 칸 | 형식 | 필수 |
|---|---|---|
| 항목명 | 글자 | 필수 |
| 담당역할 | 글자 (실명 대신 역할: 회계 담당 A 등) | 선택 |
| 예정일 | YYYY-MM-DD | 필수 |
| 결과물등록일 | YYYY-MM-DD 또는 빈칸 | 선택 |
| 마감월 | YYYY-MM (결산 작업을 하는 달) | 필수 |
| 비고 | 글자 (`합성 문제 데이터` 표시 등) | 선택 |

기준일(오늘로 보는 날)은 `meta.json` 의 `기준일` 을 쓴다 — 결과가 날마다 바뀌지 않게 고정.
(Sprint 3부터) 배포된 사이트는 매일 07:17 자동 실행 때 기준일을 그날(한국 시각)로 바꾼다 — `build.json`. 검사표(`tests/cases.md`)는 기준일 2026-11-10 고정.

## 2. 중복
- **같은 항목** = 항목명 + 마감월이 같음. 비교 전에 항목명 앞뒤 공백을 지우고, 가운데 공백은 하나로, 영문은 소문자로 맞춘다.
- **남기는 쪽**: ① 결과물등록일이 있는 줄 ② 둘 다 있거나 둘 다 없으면 예정일이 늦은 줄 ③ 그래도 같으면 파일에서 아래 줄.

## 3. 정렬
1차 상태: 지연 → 진행 → 완료 · 2차 예정일 빠른 순 · 3차(동점) 항목명 가나다순.

## 4. 제외 (이유와 함께 화면에 표시)
- 필수 칸(항목명·예정일·마감월) 빈칸
- 날짜 형식이 YYYY-MM-DD 가 아님 (결과물등록일 포함) — 단, `YYYY/MM/DD` 는 읽을 수 있는 날짜로 보고 `YYYY-MM-DD` 로 맞춘 뒤 검사한다
- 범위 밖: 예정일이 마감월 밖

## 5. 상태 판정
| 상태 | 조건 |
|---|---|
| 완료 | 결과물등록일이 있다 |
| 진행 | 결과물등록일이 없고, 예정일 ≥ 기준일 |
| 지연 | 결과물등록일이 없고, 예정일 < 기준일 |

경계 사례
| 사례 | 판정 |
|---|---|
| 예정일 당일인데 결과물 없음 | 진행 |
| 결과물은 있는데 예정일보다 늦게 등록 | 완료 |
| 예정일이 비어 있음 | 제외 (필수 칸 빈칸) |
